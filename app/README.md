# Android-приложение

Каркас Expo SDK 58 / React Native / TypeScript. Работает выбор аудиофайла в локальный cache. Добавлены типы JSON по официальному заданию и локальный Kotlin-модуль `audio-engine` с диагностикой возможностей.

ASR, диаризация и обязательная локальная LLM ещё не реализованы. Приложение не возвращает заранее подготовленные расшифровки. Наличие Kotlin-файлов не означает, что нативная сборка уже проверена.

## Начало работы

Из этой папки:

```powershell
npm ci
npm run typecheck
npm run lint
npm run android
```

`npm run android` собирает и устанавливает Android development build. Нужны JDK, Android SDK и телефон с USB debugging либо эмулятор. `JAVA_HOME` и `ANDROID_HOME` должны указывать на установленные инструменты. Папка `android/` генерируется Expo и не хранится в Git.

После первой нативной сборки для изменения только TypeScript:

```powershell
npm start
```

Нативные изменения требуют повторного `npm run android`. Для демонстрации без Metro нужна отдельная release-сборка; текущий каркас не является готовым решением задания.

## Где писать код

- `App.tsx`: стартовый экран и выбор файла.
- `src/types/transcript.ts`: внешний контракт экспорта.
- `modules/audio-engine/index.ts`: интерфейс JS ↔ Kotlin.
- `modules/audio-engine/android/`: нативная интеграция, будущий pipeline моделей.
- `../docs/brief-analysis.md`: обязательные требования, схема и критерии оценки.

## Проверки каркаса

Выполнены: TypeScript, ESLint и обнаружение audio-engine через Expo autolinking. Сборка APK, запуск на телефоне и ML-инференс пока не проверены. npm audit сообщает о 12 проблемах умеренной серьёзности в дереве зависимостей; принудительное обновление с потенциально несовместимыми версиями не выполнялось.
