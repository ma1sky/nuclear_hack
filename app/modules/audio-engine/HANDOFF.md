# Часть Артёма: первый инкремент аудиоконвейера

Реализовано: чтение RIFF WAV PCM16 mono/stereo с дополнительными чанками; сведение каналов; ресэмплинг 8–192 kHz → 16 kHz с антиалиас-фильтром; отмена; распознавание заданных интервалов через внедряемый ASR; точная структура экспорта и освобождение recognizer при успехе/ошибке/отмене.

## Интеграция

Классы в пакете `expo.modules.audioengine.audio` не зависят от Android SDK или Expo.

1. Александр передаёт `PreparedAudio` в свой `DiarizationProvider`. Он освобождает нативные ресурсы до возврата интервалов.
2. `SpeakerInterval` содержит Long `startMs/endMs` от начала записи и Int ID кластера.
3. Реальный GigaAM-адаптер реализует `SpeechRecognizer`; factory для `IntervalTranscriber` создаёт его после диаризации. `recognize` принимает FloatArray mono 16 kHz; `close` освобождает native recognizer.
4. `IntervalTranscriber.transcribe` возвращает Map с единственным полем `transcript`. Карты реплик содержат `speaker_id`, `start_ms`, `end_ms`, `text`.
5. Длинные реплики делятся на блоки до 20 секунд. Текст блоков объединяется в одну реплику с исходными метками. Speaker ID назначаются по первому появлению кластера.

`ProcessingCancellation` создаётся заново для каждой задачи. Проверяется при чтении, ресэмплинге и между ASR-блоками; текущий inference может завершиться до отмены. Прогресс передаётся callback `AudioProgress`.

## Проверка

Из этой папки: `powershell -ExecutionPolicy Bypass -File tests/test-audio.ps1`. При другом расположении Studio указать `-StudioPath`. Тестовые ответы recognizer существуют только в тестах, не в runtime приложения.

## Что ещё не готово

- Б1: запуск реального GigaAM на Redmi, фактический текст и время.
- Б2: URI/content resolver и Expo `transcribe(fileUri)`, связка с реальной диаризацией.
- Б3: M4A/AAC через MediaCodec и доставка событий в JS.
- Б4: оценка качества на эталонах Никиты.

Общий Gradle/JNI и `AudioEngineModule.kt` не менялись: это зона Александра. Текущий API приложения по-прежнему сообщает, что ASR и диаризация не подключены. Проверки на JVM не доказывают работоспособность APK или качество ASR на телефоне.

## Дополнение по Q&A

Добавлен `prepareModels()` и проверка полного локального комплекта при сборке. Gradle-модуль теперь проверяет SHA-256 assets до preBuild. Источники и упаковка описаны в `docs/model-bundle.md`. Веса пока отсутствуют, поэтому проверочная сборка намеренно останавливается до их добавления. Реальный ASR и диаризация ещё не подключены; готовность весов не изменяет capabilities.
