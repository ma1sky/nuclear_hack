# Быстрая диаризация и длинные записи — 8 ноября 2026

## Что изменено

1. **Подготовка звука потоком** (`StreamingAudioPreparer`, `StreamingWav`, `PcmStore`): запись декодируется,
   сводится в моно и переводится в 16 кГц небольшими блоками во временный PCM16-файл. Память не зависит от
   длины записи; исправляет OOM из `hour-audio-test-2026-11-08.md` (230 МБ FloatArray при лимите кучи 192 МиБ).
2. **Сегментация без плотных эмбеддингов** (`FastSegmenter`): pyannote segmentation-3.0 через ONNX Runtime,
   окна 10 с с шагом 5 с, каждый кадр решает ближайшее по центру окно, локальные спикеры окна — отдельные
   сегменты. sherpa-onnx шагает по 1 с и считает эмбеддинг для каждой пары (окно, спикер) — ~10× длины
   записи через модель голоса; это и было основным временем обработки.
3. **Спикеры** — глобальная пересборка кластеров (`Recluster`) по одному эмбеддингу CAM++ zh-en на сегмент,
   AHC average linkage, порог τ = 0,6 (выбран на dev). Модель голоса ERes2Net-base заменена на CAM++ zh-en.
   **Правило cannot-link**: два локальных спикера одного окна, звучащие одновременно, — разные люди (так же
   ограничивает кластеризацию сам pyannote). Короткая реплика поверх чужой речи больше не приписывается
   говорящему, и наложения речи не теряются.
4. Распознавание и модели голоса — до 4 потоков; резюме формируется в фоне, экран результата открывается сразу.

## DER

Коллар 0, перекрытия учитываются, шаг 10 мс, оптимальное сопоставление ID; взвешено по времени эталонной речи.
Отложенная выборка — 57 файлов: 25 русских (`mexus/ru-book-mix-10h`, голоса не пересекаются с dev) и 32 английских
(VoxConverse dev, естественная речь, 1–16 голосов), первые 120 с каждого файла.

| Конфигурация | Отложенная, DER | Коллар 0,25 с | Пропуск / ложная речь / путаница |
|---|---:|---:|---|
| v1.2 (sherpa, ERes2Net, порог 0,8) | 16,55% | 13,19% | 4,4 / 1,6 / 10,5 |
| sherpa (CAM++) + Recluster τ 0,55 (DER v2) | 9,22% | 5,68% | 4,8 / 1,7 / 2,7 |
| FastSegmenter + Recluster τ 0,6 | 9,33% | 5,64% | 5,5 / 1,6 / 2,2 |
| **FastSegmenter + Recluster τ 0,6 + cannot-link (эта версия)** | **8,61%** | **4,88%** | 3,7 / 2,0 / 2,9 |

Выбор параметров — только на dev (34 файла, RU+EN): τ 0,55 → 12,56%, **0,6 → 12,04%**, 0,65 → 12,71%;
cannot-link на dev: 12,04% → **11,53%**.
Отклонены: сшивка локальных спикеров соседних окон по зоне перекрытия (11,47% на отложенной — сливала разные
голоса), шаг 2,5 с (без выигрыша). Число спикеров угадано точно в 37 файлах из 57.

Эталонная реализация, на которой получены цифры: `tools/benchmark/fastseg_reference.py`. CI сравнивает с ней
Kotlin-`FastSegmenter` на настоящем ONNX Runtime (границы сегментов ±50 мс).

## Час реальной встречи (AMI IN1016)

Первые 3600 с встречи AMI IN1016 (4 участника, английский, много одновременной речи), ручная разметка;
подготовка `tools/benchmark/prepare_hour_case.py`, подсчёт `tools/benchmark/der_fast.py`, CI `hour-test.yml`.

| Конфигурация | DER | Коллар 0,25 с | Пропуск / ложная / путаница | Спикеров | Время диаризации часа (CI, 4 потока) |
|---|---:|---:|---|---:|---:|
| v1.2 (sherpa, ERes2Net, 0,8) | 49,6% | 44,2% | 12,1 / 1,5 / 36,0 | 82 из 4 | 41 мин |
| FastSegmenter + Recluster (без cannot-link) | 23,4% | 16,5% | 20,4 / 0,5 / 2,5 | 4 из 4 | 5,3 мин |

Пропуск речи без учёта спикеров — всего 1,6%: остальные ~19% пропуска — моменты, когда говорят двое, а в
ответе остаётся один голос. Это и устраняет правило cannot-link (результат на часе — в CI `hour-test.yml`).
AMI заметно сложнее нашей выборки: длинная встреча, четыре участника, много одновременной речи.

## Скорость

Облачный CPU, 2 потока, 5 минут естественной речи (VoxConverse); RTF = время / длительность записи.

| Этап | RTF | На 1 час |
|---|---:|---:|
| sherpa-диаризация, ERes2Net (было) | 0,242 | ~14,5 мин |
| sherpa-диаризация, CAM++ | 0,133 | ~8 мин |
| сегментация pyannote, шаг 1 с / **5 с** | 0,048 / **0,009** | 2,9 мин / **0,5 мин** |
| эмбеддинг окна 3 с: ERes2Net / **CAM++** | 72 мс / **36 мс** | |
| вся диаризация новой версии (сегментация + Recluster) | ~0,02 | ~1–1,5 мин |
| распознавание GigaAM v2 int8 | 0,109 | ~6,5 мин |

Оценка на час записи на этой машине: было ≈ 26 мин + резюме, стало ≈ 8 мин, резюме не задерживает показ
расшифровки. На телефоне время другое: замер на Redmi Note 11S ещё нужен (`tools/benchmark/run_hour_ui.py`).
