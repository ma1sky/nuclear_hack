## Метод

Импорт через системный Android File Picker, затем реальное нажатие «Расшифровать».
Используется APK, встроенные модели, автономный запуск без Metro.
Эмулятор Release12: Android 17, x86_64, 4096 МБ RAM. Это не тест Redmi Note 11S.
Время измерено внешним опросом UI и включает автоматизацию; память — максимальная
выборка dumpsys meminfo, а не точный пик выделений. Скрипт:
tools/benchmark/run_hour_ui.py --label <имя-сборки>.

## Исходный опубликованный v1.2

APK SHA-256: be3e1284aed32fdc1de937663d411f47b427873c7454806542b8c7037da460da.

Результат: **не пройден**. На подготовке записи AudioEngine.transcribe отклонён:

    java.lang.OutOfMemoryError: Failed to allocate a 230400016 byte allocation
    growth limit 201326592

Ошибка наблюдалась через 22.69 с после запуска сценария.
Максимальная выборка PSS: 100137 КБ; неудавшееся выделение в неё не входит.
Сам процесс не аварийно завершился: UI показывает ошибку и возвращение к записи.

Причина в представлении всего звука FloatArray: 3600 × 16000 × 4 = 230 400 000 байт,
что больше лимита Java-кучи процесса 192 МиБ уже для одного массива.
WavPreparer создаёт полный mono-массив; нормализация может создавать ещё одну копию.
Свободная RAM устройства сама по себе не увеличивает лимит Java-кучи.

Диаризация, ASR и LLM до результата не дошли. **DER, WER и RTF завершённой обработки
не рассчитаны**, итогового JSON нет. Указанное время нельзя называть скоростью
распознавания часового аудио.

## Следующая необходимая доработка движка

- Декодировать и нормализовать PCM блоками во временный файл, не хранить час
  FloatArray в Java-куче.
- Читать ограниченные окна для диаризации, объединять одинаковые голоса между
  окнами по embeddings, сохранять исходные смещения времени и перекрытия.
- Передавать в ASR ограниченные интервалы и освобождать буферы между ними.
- Сохранить кооперативную отмену и гарантированное закрытие ресурсов.
- Повторить этот же файл с тем же SHA-256 после исправления памяти; только затем
  считать качество диаризации по эталону.

Эта UI-итерация сохраняет исходный аудиодвижок v1.2 и не объявляет поддержку
часовых подкастов готовой. Английский AMI проверяет реальную встречу и память,
но не доказывает качество русского ASR. Для этого нужен отдельный часовой
русскоязычный разговор с ручным текстовым и speaker-эталоном.
