# Датасеты и протокол проверки

Проверено 7 ноября 2026. Основной язык приложения — русский. ASR (что сказано) и диаризацию (кто и когда говорил) оцениваем отдельно. Успех импорта файла не является измерением качества.

## Выбранные источники

| Набор | Что проверять | Эталон и формат | Как использовать |
|---|---|---|---|
| [Golos — официальный репозиторий](https://github.com/salute-developers/golos/tree/master/golos) | Русское ASR: отдельно crowd и farfield | Аудио и ручные транскрипции. Test: 11.2 ч crowd, 1.4 ч farfield; WAV test.tar около 1.3 GB | Для начала по 10–20 коротких записей из каждой части. Не скачивать train. Набор не заменяет проверку диалогов с speaker-разметкой. |
| [ru-book-mix-10h — карточка автора](https://huggingface.co/datasets/mexus/ru-book-mix-10h) | Русская диаризация: число участников, возврат голоса, границы, перекрытия | Синтетическая смесь записей аудиокниг: FLAC + RTTM, 600 файлов по минуте, 1–5 участников | Взять по 2 файла с 1/2/3 участниками. Перекодировать FLAC в WAV PCM16 mono 16 kHz. RTTM задаёт интервалы/ID, а не полный текст для WER. Это тест на смешанных реальных голосах, не естественная беседа. |
| [AMI Meeting Corpus](https://groups.inf.ed.ac.uk/ami/corpus/) и [RTTM setup](https://github.com/pyannote/AMI-diarization-setup) | Реальные встречи, несколько участников, дальний микрофон | Записи встреч и ручная разметка; для DER доступен RTTM setup | Для диаризации взять небольшой фрагмент; после обрезки сдвинуть и обрезать эталон. Английская речь не годится для оценки WER текущей русской GigaAM. |
| [Open STT](https://github.com/snakers4/open_stt) | Дополнительные русские домены, включая звонки | Валидационные части и текстовые эталоны; train включает автоматически размеченные данные | Выбирать ручную валидацию, проверять качество и исходные условия конкретной части. Автоматическую транскрипцию train нельзя считать золотым эталоном. |

### Доступность и условия

- Golos: [официальный test.tar](https://cdn.chatwm.opensmodel.sberdevices.ru/golos/test.tar), [контрольные суммы](https://github.com/salute-developers/golos/blob/master/golos/md5sum.txt), [лицензия на русском](https://github.com/salute-developers/golos/blob/master/license/ru.pdf). У Golos собственный лицензионный документ; не обозначать его автоматически как MIT/CC0. Перед распространением аудио проверить его условия.
- ru-book-mix: карточка заявляет CC BY 4.0 и требует указания исходных источников речи/шума. Сохранять attribution; использовать только для оценки. Автор прямо предупреждает о повторении исходных голосов и непригодности для обучения на этом benchmark.
- AMI: официальный сайт указывает CC BY 4.0 для сигналов, транскрипций и части аннотаций. Сохранять авторство; различать лицензии корпуса и вспомогательного кода.
- Open STT: агрегирует разные источники; лицензия кода не доказывает единые права на все аудиозаписи. Условия выбранной части проверять отдельно.
- [VoxConverse](https://www.robots.ox.ac.uk/~vgg/data/voxconverse/): полезный benchmark, но официальный сайт сейчас сообщает о недоступности аудио. Поэтому он не выбран как быстрый путь к первому тесту.

Большие аудиоархивы не добавлять в Git или APK. Хранить локально в игнорируемой `recordings/`; в Git — источники, выбранные ID, SHA-256, эталоны, параметры оценки и результаты. Новые собственные записи команды держать отдельно от публичных benchmark: они лучше проверяют именно русскую встречу/звонок.

## Минимальный набор на хакатон

1. ASR: 20 crowd + 20 farfield из test-раздела Golos, фиксированный список ID до первого измерения.
2. Диаризация: 6 минут ru-book-mix (по 2 записи с 1/2/3 участниками). Отдельно пометить записи с перекрытием; не исключать их молча из отчёта.
3. Сквозной сценарий: собственные WAV и M4A по 1–3 минуты, два и три участника, возвращение первого голоса и короткие ответы. Эталон вручную, независимо от результата приложения.
4. Негативные примеры: 10 секунд тишины, повреждённый файл, неподдерживаемый формат. Тишина должна давать пустой transcript.

Этот набор — smoke/regression, не репрезентативная оценка всех разговоров. Результаты эмулятора не экстраполировать на скорость/память Redmi.

## Подготовка файлов

Если установлен FFmpeg:

```powershell
ffmpeg -i source.flac -ac 1 -ar 16000 -c:a pcm_s16le test.wav
ffmpeg -i test.wav -c:a aac -b:a 96k test.m4a
adb push test.wav /sdcard/Download/
adb push test.m4a /sdcard/Download/
```

Конверсия всего файла сохраняет временную шкалу, обрезка меняет её. Длительность и эталон проверять после конверсии. WAV/M4A импортируются через системный выбор файла приложения.

## Метрики и отчёт

- **WER**: `(S + D + I) / N` на словах. Для эталона и результата одинаково: нижний регистр, `ё → е`, удаление пунктуации, схлопывание пробелов; числа в слова не переводить. Сначала склеить реплики по времени, чтобы оценить ASR без ошибки speaker mapping. Зафиксировать версию нормализации. Не делить на ноль при пустом эталоне: отдельно считать ложные слова на тишине.
- **DER**: сумма missed speech, false alarm и speaker confusion относительно эталонного времени речи. Сопоставить произвольные ID голосов между эталоном и предсказанием. Перед сравнением явно зафиксировать collar (например, 0 или 0.25 с) и учёт overlapping speech; разные настройки не смешивать в одной цифре.
- **Сквозной результат**: доля неверно приписанных реплик после сопоставления голосов, ошибки границ и число потерянных коротких ответов. Не выдавать эту собственную метрику за стандартный DER.
- **Скорость**: время подготовки, диаризации, ASR и LLM; общий RTF = время обработки / длительность аудио. Сохранять модель, ABI, устройство, RAM, Android, холодный/повторный запуск. Скорость эмулятора — диагностическая.
- **Резюме**: проверять отдельно по исходному диалогу: нет ли выдуманных фактов, сохранены ли решения. ASR-датасет не содержит эталонного резюме по умолчанию.

Для каждой записи: `source`, `split`, `file_id`, SHA-256 аудио, длительность, параметры преобразования, эталон, фактический строгий JSON, время стадий, настройки метрики и результат. Диагностические поля хранить рядом, не добавлять их во внешний JSON задания. Тестовые файлы не использовать для подгонки настроек с последующей публикацией результата как независимой оценки.
