Обновлено: 6 ноября 2026 года.

> План уточнён по [официальному PDF](brief-analysis.md). Локальная LLM обязательна; экспорт должен соответствовать схеме задания.

## 1. Цель

Пользователь выбирает запись разговора на Android, запускает обработку и получает сохранённый диалог: номер участника, начало и конец реплики, текст. Вся обработка аудио выполняется на телефоне.

Автоматическое разделение голосов называется диаризацией. Оно присваивает участникам условные номера; определение имён людей по голосу в MVP не входит. Пользователь может переименовать участников вручную.

## 2. Объём MVP

### Обязательные функции

- [ ] Импорт локального WAV: PCM 16-bit, mono, 16 kHz.
- [ ] Автоматическое выделение интервалов и группировка по говорящим.
- [ ] Распознавание русской речи на устройстве (язык экспертных записей уточнить).
- [ ] Реальное использование локальной LLM на Android; модель, runtime и роль пока не выбраны.
- [ ] Экспорт по точной схеме: transcript[] → speaker_id (string), start_ms/end_ms (integer), text (string).
- [ ] Структурированные реплики с устойчивым speakerId внутри записи.
- [ ] Начало и конец реплик относительно исходной записи.
- [ ] Экран диалога и состояния обработки.
- [ ] Сохранение результата между запусками.
- [ ] Экспорт JSON и TXT.
- [ ] Понятная ошибка для неподдерживаемого файла или отсутствующей модели.
- [ ] Release APK, который обрабатывает новую запись без Metro, ноутбука и сети.

Официальные входные форматы не заданы; WAV-only — промежуточный этап и не подтверждённое достаточное решение для сдачи.

Целевой сценарий первой версии: русский язык, 2–3 участника, 1–5 минут, преимущественно последовательная речь. Это проектные ограничения, а не уже подтверждённые возможности. Длительность и число участников необходимо проверить на тестах и сверить с заданием.

### После работающего основного сценария

1. Переименование участников.
2. Поддержка M4A с декодированием и ресэмплингом.
3. Прослушивание записи с переходом к выбранной реплике.
4. Ручное исправление текста.
5. Запись с микрофона.

### За пределами первой версии

Потоковая расшифровка, суммаризация, аккаунты и синхронизация, идентификация людей между записями, полноценное разделение одновременно звучащих голосов.

## 3. Роли четырёх участников

| Роль | Ответственность | Первый результат |
| --- | --- | --- |
| 1. Нативная интеграция и диаризация | Expo Module, sherpa, сегментация и speaker embeddings | WAV → реальные интервалы с speakerId → TypeScript |
| 2. Распознавание и pipeline | GigaAM, локальная LLM, нарезка интервалов, объединение результата | Интервалы → текст с абсолютными временными метками |
| 3. Интерфейс | Импорт, состояния, список реплик, переименование | UI на тестовом JSON, затем подключение к модулю |
| 4. Данные и QA | Сохранение, экспорт, аудиофикстуры, установка APK и проверки | JSON/TXT и воспроизводимое офлайн-демо |

Назначить людей по фактическим навыкам. Первые два участника работают в отдельных Kotlin-классах одного модуля. Один из них отвечает за общую конфигурацию Gradle; изменения сборки согласуются до слияния.

## 4. Порядок реализации и зависимости

### Этап A. Проверка стека — первые 2–3 активных часа

- [ ] Выбрать основной и резервный телефон; записать модель, Android и RAM.
- [ ] Создать Expo-проект и локальный модуль audio-engine.
- [ ] Собрать приложение на физическом устройстве.
- [ ] Подключить совместимые Kotlin API и нативные библиотеки sherpa одной версии.
- [ ] Загрузить модели из локального каталога приложения.
- [ ] Пропустить короткий WAV через диаризацию и вернуть интервалы в TypeScript.
- [ ] Проверить GigaAM на том же устройстве, измерить время и память.
- [ ] Выбрать локальную LLM, согласовать её роль и проверить реальный вызов на телефоне с учётом RAM.

Условие перехода: реальный результат ASR, диаризации и локальной LLM на телефоне. Заглушка и успешный вызов Kotlin сами по себе не подтверждают работоспособность ML.

### Этап B. Полный сценарий — к пятому активному часу

- [ ] Скопировать выбранный файл в доступный приложению локальный каталог.
- [ ] Выполнить диаризацию всей записи.
- [ ] Распознать каждый интервал и сохранить его исходные границы.
- [ ] Выполнить выбранную функцию локальной LLM и проверить сохранность фактов, меток и участников.
- [ ] Вернуть список реплик в UI.
- [ ] Сохранить результат в JSON.

Условие перехода: выбранный пользователем WAV превращается в диалог на экране без сети.

### Этап C. Завершение MVP

- [ ] Экспорт TXT/JSON.
- [ ] Повторное открытие сохранённой расшифровки.
- [ ] Ошибки импорта, тишины, отсутствующих моделей и повторного запуска.
- [ ] Стадия обработки и счётчик распознанных реплик.
- [ ] Только после этого — дополнительные функции из списка выше.

### Этап D. Сдача

- [ ] Установить release APK заново и проверить наличие моделей.
- [ ] Закрыть Metro, включить авиарежим, обработать новую запись.
- [ ] Проверить сохранение и экспорт.
- [ ] Подготовить видео, краткую инструкцию и список ограничений.
- [ ] Проверить состав сдачи и отправить до стопкодинга.

## 6. Проверки качества

Подготовить короткие записи с ручным текстом, границами и принадлежностью реплик:

| Запись | Что проверяем |
| --- | --- |
| Один участник | Голос не распадается на несколько speakerId |
| Два участника | Смена и возвращение говорящего |
| Три участника | Количество групп и устойчивость меток |
| Короткие «да/нет» | Потери текста и ошибки назначения участника |
| Тишина | Отсутствие выдуманных реплик и корректное завершение |
| Шум и небольшое перебивание | Границы применимости и поведение при сложной записи |

Для каждой записи фиксировать длительность, время обработки, пиковую память при доступном измерении, ошибки текста и назначения участника. Кластерные номера сравнивать с эталоном после сопоставления голосов: сами номера произвольны.

RTF = время обработки / длительность записи. Предварительный ориентир для короткого демо — RTF ≤ 2; он не подтверждён и требует измерения на выбранном устройстве. Фактические показатели сообщать вместе с моделью телефона и параметрами моделей.

## 7. Риски и действия

| Риск | Действие |
| --- | --- |
| Сложности Gradle/JNI | Проверять нативную сборку первым делом, закрепить совместимые версии |
| Недостаточно памяти | Ограничить запись, обрабатывать модели последовательно, освобождать нативные ресурсы |
| Низкая скорость | Измерить на телефоне, начать с INT8 и CPU, затем менять параметры по результатам |
| Короткие реплики распознаются плохо | Проверить границы и контекст; более длинные ASR-фрагменты с выравниванием оставить улучшением |
| Одновременная речь | Зафиксировать ограничение; диаризация не заменяет разделение аудиоисточников |
| Отставание | Сократить дополнительные форматы и функции, сохранить диаризацию, текст и метки |

## 8. Вопросы организаторам

- Правила кода до старта, использования открытых библиотек и моделей.
- Точное начало окна и часовой пояс дедлайна.
- Обязательные форматы, язык, длительность и число участников.
- Устройство проверки, скрытые записи, допустимое время обработки.
- Автоматическое число участников и требования к одновременной речи.
- Точность меток, структура экспорта, обязательность записи с микрофона.
- Допустима ли предварительная загрузка моделей, что должно работать при первой установке без сети.
- Критерии оценки и комплект сдачи.
