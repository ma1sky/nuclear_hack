# Перенос интерфейса из Figma — 7 ноября 2026

Источник: [Нейро-стенографист, App screens](https://www.figma.com/design/STDVjRGdWcuRvW66QrYfUJ/?node-id=0-1). Состояние макетов прочитано через Figma MCP, с контекстом компонентов и скриншотами 29 экранов. Динамические примеры имён, реплик, длительности и процентов заменены фактическими данными приложения.

## Архитектура

- Expo Router: `app/src/app/`, общий `WorkspaceProvider` держит задачу обработки и результат при переходах.
- React Native Reusables Button, Card, Input; действующие токены цветов и размеров; локальный Inter.
- Оригинальные SVG из Figma в `app/assets/figma/`; `manifest.json` содержит источники, размеры и SHA-256. `icons.ts` задаёт локальные импорты и исходную геометрию. Android status bar — настоящий системный, время 9:41 из макета не имитируется.
- `expo-audio`: воспроизведение и микрофон. Аудио хранится в приватном каталоге; метаданные диктофона отделены от расшифровок.
- ASR/диаризация/LLM продолжают выполняться локально и последовательно. Расширенное событие подготовки передаёт длительность и реальную RMS-огибающую; оценочный JSON не получает новых полей.

## Данные и устойчивость

- Импортированный файл копируется из cache в постоянное хранилище перед обработкой. Диктофон сохраняет исходное аудио до запуска ASR; отмена обработки не удаляет сохранённую аудиозапись.
- Имена участников сбрасываются при новой записи и сохраняются только в своём результате. Повторное резюме обновляет историю.
- Выход с незавершённой записью защищён; при уходе приложения в фон микрофон ставится на паузу. Полноценная фоновая запись не заявляется.
- Производственные экраны не используют фиктивные реплики, проценты или случайную волну. При отсутствии огибающей у старого результата показывается линейная шкала; после новой обработки — измеренная огибающая.
- Входы 8 часов/5 ГБ, MP3 и качество ML этим изменением не объявляются поддержанными или улучшенными.

## Проверки и сборки

Проверка выполнена на Android 17 / API 37, эмулятор x86_64 с 4 ГБ RAM. Release APK содержит arm64-v8a и x86_64, JS и пять файлов моделей. На физическом Redmi и ARM эти экраны пока не проверены. Предыдущий кандидат DER 0.8 сохранён отдельно; этот перенос не меняет настройки диаризации.

- TypeScript, ESLint, три теста интеграции/экспорта, три теста дизайн-системы, два теста аудиотеки и проверка токенов проходят после финальных изменений.
- На сборке `f399e88eb372` проверены настоящая запись AAC/M4A, остановка таймера на паузе (01:31), продолжение до 01:34, прослушивание, сохранение, переименование, повторное открытие после перезапуска и удаление несохранённого дубля.
- На ней же новая четырёхсекундная запись Golos прошла ASR → LLM → сохранение за 27,03 с. Это один короткий smoke-тест, а не оценка качества подкастов.
- На сборке `fc801727dd17` в авиарежиме проверены новая обработка, отмена именно во время LLM с сохранением текста, повторная генерация резюме, строгий JSON, открытие системного экспорта JSON/TXT, повторная запись с паузой и сохранение. Время отмены не измерено.
- Пользовательское имя участника восстановлено после перезапуска. JSON сохранил исходный `speaker_1`, целые миллисекунды и только поля задания. Системный диалог экспорта открыт и закрыт; отправка в сторонние приложения не выполнялась.
- Финальная сборка исправляет обнаруженное на предыдущем APK обновление подписи скорости на паузе и повторное воспроизведение после конца файла. Проверены полный цикл скорости на паузе, перемотка к началу/концу, переход к реплике, повтор после конца и подтверждённое удаление двух собственных тестовых аудиозаписей. Для четырёхсекундного клипа сняты быстрые кадры: медленный UI-дамп иногда успевал только после завершения. SHA-256 и проверки записаны в машинном отчёте.

Результаты: `artifacts/test-results/figma-ui-2026-11-07.json`; выбранные фактические снимки — в соседней папке `figma-ui-2026-11-07/`. Сырые аудиозаписи и рабочие дампы находятся в игнорируемом `recordings/figma-ui-smoke/` и не добавляются в Git.

## Ограничения и оставшаяся работа

- Маленькая Qwen в тесте заменила «шестьдесят тысяч тенге» на «1000000 тенге». Это фактическая ошибка резюме; ASR и экспорт остались неизменны. Резюме требует проверки человеком. Улучшение качества LLM — отдельная работа.
- Нет нового прогона десяти длинных подкастов: перенос UI не подтверждает улучшение WER/DER или скорость на Redmi. Поддержка 8 часов/5 ГБ и MP3 не проверялась.
- Основные экраны сопоставлены с макетами, но полное пиксельное совпадение всех 29 состояний не заявляется. Высота контента зависит от настоящих данных и системных отступов. В диктофоне и карточке сохранённого аудио есть небольшие отличия расположения пояснений.
- Переименование аудио, действия с записью, удаление аудио и отказ от несохранённой записи используют собственные диалоги. Удаление истории и подтверждение отмены при возврате с обработки пока используют Android Alert.
- У старых результатов нет сохранённой огибающей: плеер показывает линейную шкалу. Диктофон создаёт AAC/M4A; иллюстративный WAV из Figma не используется для маскировки формата.
- Фоновая запись не реализована: при уходе в фон диктофон ставится на паузу. Отказ в доступе к микрофону реализован в коде; окончательный сценарий выдачи/отзыва разрешения нужно повторить на целевом телефоне.
- Сборка подписана тестовым ключом текущего проекта. [GitHub Release с APK](https://github.com/ma1sky/nuclear_hack/releases/tag/ui-2026-11-07).
