Удалённая версия частично лучше по измеренной диаризации. Она не устраняет основную проблему лишних speaker ID и пока не подтверждает точность подкастов. Свежие изменения получены через git fetch; рабочая ветка и локальные результаты тестов сохранены.

## Что изменилось

- Для WAV и декодированных M4A добавлено общее усиление по 98-му процентилю абсолютной амплитуды: до 8 раз, с мягким ограничителем. Это один коэффициент на файл, а не выравнивание каждого говорящего и не подавление шума.
- Кластеризация: threshold 0.5 → 0.55. minDurationOn явно задан 0.2 с и совпадает с прежним Android-default; minDurationOff: 0.5 → 0.3 с. Android-defaults сверены через javap с фактическим AAR 2.0.1. У Python minDurationOn по умолчанию 0.3 с, поэтому для обеих конфигураций явно выставлено Android-значение 0.2 с.
- ASR: blankPenalty 0 → 1.2.
- На внешних границах интервала ASR добавлено по 120 мс контекста. Внутренние границы блоков по 20 секунд по-прежнему не получают перекрытия.

Для удалённого варианта воспроизведён алгоритм нормализации Kotlin на NumPy float32. Это проверка настроек и моделей, не запуск нового APK. Проверялся совместный эффект изменений; вклад каждого параметра отдельно не измерялся. Первоначальные прогоны с Python-default 0.3 с исключены и заменены корректной Android-конфигурацией.

## Риски и непроверенные изменения

1. Padding захватывает соседние реплики. При смежных интервалах [0,1000] и [1000,2000] мс вход ASR становится [0,1120] и [880,2000]: 240 мс звука используются дважды. В коде нет удаления повторов или переназначения слов говорящим. Это риск повторов и неверного speaker_id; реальный случай в новом APK ещё не проверен. Экспортированные интервалы при этом остаются исходными и могут не охватывать часть распознанного контекста.
2. Усиление поднимает и шум. Тихий собеседник рядом с громким не получит отдельного усиления. При срабатывании нормализации выделяется дополнительный FloatArray размером со всю запись: для 24:05 mono 16 kHz — около 88 МиБ, без учёта других буферов. Android-пик этой версии не измерялся.
3. Blank penalty 1.2 не проверен на размеченных подкастах и шумовой речи. Нет подтверждения, что он уменьшает пропуски без роста вставок.
4. LLM, промпт и сведение блоков не изменились. Исправления ранее найденного искажения чисел и длительного резюме этот коммит не содержит.
5. Новых тестов или результатов качества в удалённом коммите нет. Поддержка новых параметров подтверждена через API локального Android AAR. Полная сборка и запуск нового APK не выполнялись. TypeScript и ESLint общей для двух версий части проходят; git diff --check проходит.

## Решение

Использовать удалённый коммит как кандидата для дальнейшей работы: улучшение диаризации измерено, но задача качества остаётся открытой. Перед новым релизом проверить padding на коротких ответах и сменах говорящих, собрать отдельный APK и повторить десять записей с сохранением прежнего baseline. Для утверждений о точности подкастов нужны ручные текстовые и speaker-эталоны. Локальные инструменты и отчёты нельзя потерять при последующем объединении.

В ходе этой проверки выполнен только fetch. main, установленный APK и исходный ML-код рабочего дерева не обновлялись.
