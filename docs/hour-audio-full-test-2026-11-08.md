# Полный часовой тест после исправления OOM — 8 ноября 2026

**Стабильность пройдена на этом файле; качество диаризации не прошло проверку.**
Запуск без отмены дошёл до ASR, локального резюме, сохранения и экспорта.
Прежний OutOfMemoryError не повторился.

- Release12, Android 17, x86_64, RAM 4096 МБ, авиарежим. Без Metro.
  Хост AMD Ryzen 5 3600, 6 ядер / 12 потоков; ML работает на CPU, два потока.
  Это не измерение на Redmi Note 11S.

  b5fb30861cf866ed39f990527a3400453c23cf405d2849a656b1c6bec0190fca.
  Локальный APK: artifacts/emulator/nuclear-stenographer-oom-fix.apk.
- Java heap growth limit 192 МиБ не увеличивался.

Полный сценарий: **2084,56 с = 34 мин 44,56 с**, RTF **0,579**.
Время включает внешний опрос UI и не является чистым временем инференса.

| Этап | Приблизительное время |
|---|---:|

Границы наблюдались опросом UI: подготовка 5,00 с, диаризация 10,88 с,

в выборку. Не следует интерпретировать таблицу как точный профилировщик.

После обработки и повторного открытия результата: 289 130 КБ, около 282 МиБ.
Это не точный пик памяти и не доказательство отсутствия утечки после многих часов.

## Функциональные проверки

- Обработаны все 594 обнаруженных интервала; итоговый JSON содержит 312 непустых реплик.
- Строгая схема: только transcript, speaker_id/start_ms/end_ms/text.
  Все ID строковые, метки целочисленные и лежат в пределах исходного часа.
- Последний непустой интервал заканчивается на 3 546 080 мс; тишина и пустой ASR
  не обязаны создавать реплики до последней миллисекунды файла.
- Локальное резюме сформировано и сохранено.
- Открылось настоящее системное окно экспорта JSON с файлом
  hour-ami-IN1016_export.json. Получателя не выбирали, файл никому не отправлялся.
- Сохранённые часовая расшифровка и резюме повторно открываются из истории.
- Полный экспорт извлечён из реального UI, не подменён модельным или эталонным текстом.

## Качество: неудовлетворительно

Предсказано **73 участника вместо 4**. Видна сильная фрагментация голосов.

**DER по конечным экспортированным репликам — 71,62%**, ниже лучше.
Оптимальное взаимно однозначное сопоставление ID, шаг 10 мс, collar 0,
перекрытия включены. Код: tools/benchmark/score_benchmark.py и speaker_assignment.py.

| Составляющая | Секунды речи участников |
|---|---:|
| Пропуски | 2231,27 |
| Ложная активность | 18,14 |
| Ошибки принадлежности | 995,92 |
| Речь эталона, суммарно по участникам | 4531,46 |

Это секунды речи с учётом одновременно говорящих, поэтому знаменатель больше
длительности файла. Метрика рассчитана **по итоговому JSON**, а не по необработанным
интервалам диаризатора: пустой результат ASR удаляет реплику и влияет на пропуски.
По этой цифре нельзя изолированно оценить только алгоритм сопоставления голосов.

ASR GigaAM здесь русский, вход английский. Получено 801 слово, в основном
кириллическая передача английского звучания и некорректный текст.
Это не качественная английская расшифровка. WER намеренно не приводится
как оценка русского ASR; количество слов тоже не заменяет WER.
Корректность смысла резюме при таком исходном тексте не подтверждена.

## Вывод и следующая проверка

- Исправление полного FloatArray выдержало полный часовой сценарий на эмуляторе.
- Объявлять точную обработку часовых подкастов готовой нельзя.
- Проверить сопоставление embeddings между окнами и создание новых ID при
  коротких фрагментах без готового embedding; затем калибровать пороги по DER.
- Сохранить отдельные сырые интервалы диаризации для оценки до фильтрации ASR.
- Добавить измеряемый прогресс по окнам: 18 минут без счётчика неудобны пользователю.
- Нужна отдельная часовая русскоязычная запись с ручным эталоном и тест на Redmi.
- Повторные часовые прогоны для проверки накопления памяти пока не выполнены.
