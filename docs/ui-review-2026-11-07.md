## Наблюдение → решение → результат

1. Несколько разных акцентных цветов экспорта конкурировали за внимание. Применена иерархия готовых вариантов RNR: основной JSON, вторичные TXT/просмотр. Группа действий отделена общей границей; действия сохраняют одинаковую минимальную область нажатия.
2. У интерфейса не было общей основы цветов/размеров. Добавлены семантические токены и готовые Button/Text/Card/Badge/Input/Separator. Существующие модальные сценарии используют общую оболочку и те же компоненты.
3. Фиксированный условный прогресс создавал ложное ощущение измерения. Для неизвестного прогресса оставлен индикатор ожидания; для ASR показано число завершённых реплик.
4. Маленький бейдж имени затруднял переименование. Имя стало кнопкой с минимумом 48 dp, переносом длинной подписи и accessibilityLabel.
5. Технические подписи и дублирование времени в миллисекундах перегружали чтение. На основном экране оставлены пользовательские названия стадий и часы; JSON хранит исходный контракт.
6. На первом веб-рендере выявлена испорченная кодировка части русских строк при переносе файлов. Исправлена явным UTF-8; повторная сборка и просмотр подтвердили читаемые подписи.

Общие опоры проверены на снимках: карточки снаружи x=16, содержимое x=32; кнопки занимают ширину своей группы; заголовки самостоятельных секций стоят на внешней опоре. Время в реплике может переходить на следующую строку под длинным именем. Это предпочтительнее обрезания имени или уменьшения области нажатия.

## Пределы вывода

Проверена композиция веб-рендера реальных RN-компонентов и конкретные UI-взаимодействия. Не измерялись удобство на пользователях, WER, RTF и работа моделей. Не подтверждены нативные клавиатура/TalkBack/font scaling, release APK и инференс на Redmi. Известный блокер предыдущей Gradle-сборки — TLS при получении Maven-зависимостей — нельзя считать устранённым этой работой; см. [integration-review.md](integration-review.md).

После добавления safe-area-context и Uniwind нужна новая native-сборка; только перезапуск Metro не обновляет уже установленный development build. Проверка на устройстве обязательна перед сдачей. Тёмная тема и дополнительные сценарии записи не добавлены.

Повторный fetch перед завершением не удался: GitHub TLS handshake завершился ошибкой и в Schannel, и в OpenSSL с включённой проверкой сертификатов. Анализ относится к успешно полученному в начале работы 1f01c85; отсутствие более новых remote-коммитов в конце работы не подтверждено. Позже, при подготовке релиза, fetch успешно выполнен через рабочий TLS-маршрут; main и origin/main совпадали. Результаты публикации доступны в README.
