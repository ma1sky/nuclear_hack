# v1.2.3 — ускорение локальной обработки (предварительный релиз)

Экспериментальная сборка TitaNet. Есть измеренное ускорение и отдельные регрессии DER. Стабильный релиз v1.2 остаётся доступным.

## Что изменилось

- Eres2Net заменён на NVIDIA NeMo TitaNet-Small; параметры сопоставления голосов откалиброваны отдельно для модели. Профиль Eres2Net сохранён для сравнительных сборок.
- Диаризатор и дополнительный extractor переиспользуются между окнами записи; участники назначаются совместно, отсутствующие признаки не создают фиктивные ID.
- ASR использует четыре потока на x86_64 с минимум четырьмя доступными CPU. Для ARM сохранены два потока до проверки телефона.
- Текст сохраняется и доступен для просмотра/экспорта сразу после ASR. Локальное резюме Qwen продолжается отдельно и не меняет JSON.
- Исправлены повторный переход на экран результата и состояние после отмены резюме; текст остаётся сохранённым, следующий запуск обработки работает.
- Большое аудио подготавливается в PCM на диске, вместо загрузки всей записи в Java-кучу. Окна диаризации ограничены 120 с, блоки ASR — 20 с.
- APK содержит ARM64/x86_64, JavaScript и все пять моделей; загрузка весов при запуске не требуется.

## Измеренное ускорение

Android 17, x86_64-эмулятор, 6 vCPU, 4 ГБ RAM, авиарежим; сравнение с предыдущим Eres2Net-кандидатом, уже имевшим ранний показ текста.

| Один и тот же вход | Текст: раньше → сейчас | Весь цикл с LLM: раньше → сейчас |
|---|---:|---:|
| Трёхминутная русская размеченная синтетическая запись | 98 → 62 с | 192 → 144 с (**−25%**) |
| Пятиминутный естественный русский подкаст | 157 → 94 с | 339 → 248 с (**−27%**) |

Отдельная проверка Android-движка на трёх многоконных файлах: время диаризации 145.57 → 64.58 с, примерно **в 2.25 раза быстрее**. Взвешенный DER этой серии 43.07% → 33.63%; для двух многоголосных случаев отдельно 49.97% → 40.73%.

## Ограничения и регрессии

- На сложном rec_0275 DER полного экспорта **ухудшился с 27.84% до 30.28%**. В результате 4 известных ID при 3 эталонных. Снижение числа ID само по себе не означает повышение качества.
- Качество не улучшилось на каждом файле. На тяжёлой синтетической смеси DER остаётся 55.15%; похожие голоса, короткие реплики и перебивание остаются проблемой.
- Длинные размеченные примеры созданы повторением 60-секундных смесей с сохранением ID. Это проверка окон, не независимые трёхминутные разговоры. Часть голосов ранее встречалась в экспериментах.
- У естественных подкастов нет ручного эталона: WER/DER для них не заявляется. WER 0 подтверждён только на одном коротком Golos-примере из 6 слов.
- Скорость Redmi Note 11S и новая чистая установка на телефоне не проверены. Приведённые времена — отдельные наблюдения эмулятора с опросом UI, не гарантия для устройств или часовых подкастов.
- Полный часовой прогон нового TitaNet APK не выполнялся. Часовой WAV ранее прошёл OOM-проверку старой Eres2Net-сборки; это не подтверждение часового качества нового релиза.
- Лимит LLM оставлен 160 токенов: вариант 96 обрезал длинный ответ. Маленькая Qwen может пропускать факты и нарушать формат; её резюме следует сверять со стенограммой.
- Наблюдавшийся максимум PSS около 840 МиБ на пятиминутном подкасте — максимум выборок, не инструментированный пик и не доказательство отсутствия утечек.

## Проверки и поставка

Полный кандидат проверен на WAV 180 с, WAV-подкасте 300 с, AAC/M4A 60 с и Golos 4 с. Проверены строгий JSON, целые временные метки, сохранение, локальное резюме, экспорт во время LLM, неизменность JSON после резюме/отмены и повторный запуск после отмены. В финальной серии OOM не было, вкладка результата не сбрасывалась.

Измерения выше получены на функциональном кандидате SHA-256 `1949fe7457fb9abfeed62d331755ae39bbe8e801c6bb36a5c84d9488cb73a8d4`. Перед публикацией подняты versionName/versionCode через Expo; отдельная проверка обновления и целостности релизного APK фиксируется ниже. История при проверке обновления не удаляется.

APK крупный, поскольку модели встроены. Контрольная сумма прилагается в SHA256SUMS.txt. Для обновления поверх другой сборки также должна совпадать подпись приложения; данные перед переустановкой нужно сохранить.

Подробный протокол, источники и агрегаты находятся в `docs/runtime-options-2026-11-08.md` и `artifacts/test-results/runtime-options-2026-11-08/`. Полные тексты подкастов, аудио и скриншоты не публикуются в Git. Веса и APK не добавляются в обычный Git; APK прикреплён к этому релизу.

- Версия 1.2.3, versionCode 12; ARM64 и x86_64.
- Файл: `nuclear-stenographer-1.2.3-runtime-preview-arm64-x86_64.apk`; 911430194 байт (около 911 МБ).
- SHA-256: `28487befa57bae896c252ea30b8082a2bf11ae732799fb44b5ef7a3b43487af7`.
- Подпись совпадает с протестированным кандидатом; используется тестовый ключ, не production-подпись.
- Все файлы моделей и нативные библиотеки совпадают с кандидатом по CRC и размеру. Полные длительные замеры относятся к кандидату, а не повторному прогону финального APK.
- `adb install -r` завершился `Success`; после установки подтверждены versionName 1.2.3 и versionCode 12, данные не очищались.
- Повторный UI-прогон финального APK **не завершён**: первая попытка остановилась до инференса на подключении UiAutomation, повтор прерван восстановлением ADB. После перезагрузки эмулятор оставался offline. Это не засчитано как успешное распознавание финального APK; функциональные замеры относятся к указанному кандидату.
- TypeScript, ESLint и release-сборка Gradle прошли; проверки аудиодвижка и двух профилей упаковки моделей ранее прошли на этом наборе изменений.
