# Дизайн-система нейро-стенографиста

Статус: внедрена в React Native UI 7 ноября 2026 года. Основа — **React Native Reusables**, готовый нативный порт подхода shadcn/ui, ветка registry `uniwind`. Это исходные компоненты библиотеки с локальными адаптациями, а не веб-компоненты внутри WebView.

## Основание и выбор

Пользовательский сценарий: выбрать запись встречи или звонка → дождаться обработки → прочитать реплики → проверить резюме → экспортировать результат. Критичны читаемость длинных реплик, различимость участников и честное состояние продолжительной локальной обработки.

До изменения у кнопок экспорта были три конкурирующих цвета, имя участника было маленькой областью нажатия, а некоторые стадии показывали условные 60%. Новая система задаёт одно главное действие, нейтральные поверхности и измеряемый прогресс. Цвет участника дополняет его имя; цветом нельзя кодировать личность без текста.

Рассмотрены: сохранение всех локальных StyleSheet и собственная имитация shadcn; прямой перенос web shadcn; готовые нативные исходники. Выбран последний вариант: готовые варианты и семантические токены уменьшают количество собственного UI-кода, при этом сохраняются нативные View, Text, Pressable и TextInput. Смена библиотеки не подтверждает качество ASR или работу APK.

Источники:

- [shadcn/ui](https://ui.shadcn.com/docs) — распространение исходников компонентов, которыми владеет проект.
- [Семантические токены shadcn](https://ui.shadcn.com/docs/theming) — пары background/foreground и роли primary, muted, destructive.
- [React Native Reusables](https://github.com/founded-labs/react-native-reusables) — готовая реализация для React Native, MIT.
- [Uniwind: подключение](https://docs.uniwind.dev/quickstart) и [темы](https://docs.uniwind.dev/theming/basics) — Tailwind 4, Metro, импорт CSS в компонент приложения.
- [Carbon: выравнивание кнопок](https://www.carbondesignsystem.com/building-blocks/core/components/button/guidelines) и [NN/g: близость](https://www.nngroup.com/articles/gestalt-proximity/) — согласованная геометрия действий и группировка связанных данных; конкретные размеры ниже выбраны для нашего приложения.

В первой версии только светлая тема. `app.json` и `Uniwind.setTheme('light')` согласованы. Наличие `dark:` вариантов в исходниках библиотеки не означает готовность тёмной темы.

## Основы

| Роль | Значение | Применение |
|---|---|---|
| background / foreground | `#fafafa` / `#18181b` | Фон приложения и основной текст |
| card / cardForeground | `#ffffff` / `#18181b` | Карточки и диалоги |
| primary / primaryForeground | `#18181b` / `#ffffff` | Главное действие в текущей зоне |
| muted / mutedForeground | `#f4f4f5` / `#52525b` | Подписи, метаданные, подложки |
| border | `#e4e4e7` | Разделение поверхностей |
| input | `#71717a` | Различимая граница поля ввода |
| ring | `#2563eb` | Фокус |
| destructive / errorSurface | `#b91c1c` / `#fef2f2` | Ошибка с текстовой причиной |
| success / successSurface | `#166534` / `#f0fdf4` | Подтверждённый успех, если нужен |
| warning / warningSurface | `#92400e` / `#fffbeb` | Предупреждение с объяснением |

Шкала расстояний: **4, 8, 12, 16, 24, 32 dp**. Внешний отступ карточек — 16, внутренний — 16: внешний край на x=16, текст карточки на x=32. Заголовки самостоятельных секций стоят на внешней опоре x=16. Зона экспорта имеет собственную границу на всю ширину и внутренний отступ 16. Не складывать ещё один такой же padding во вложенном компоненте.

Радиусы: 6/8/12/16 dp. Текст: системный шрифт Android; 12 sp для времени, 14 для пояснений, 16 для реплик и действий, 20 для заголовка карточки, 24 для названия приложения. Реплики — межстрочный интервал 28, подписи — 20. Системное масштабирование текста сохраняется. Декоративные тени в основных карточках отключены.

Минимальная область кнопки **48×48 dp**, высота увеличивается под переносы. Длинное имя файла или участника переносится; важное имя на основном экране нельзя заменять многоточием. Цвета участников выбираются детерминированно по ID из шести пар в tokens.json; они могут повторяться при большом числе участников. Точное соответствие хранится в ID/имени, а не в оттенке.

## Контракт компонентов

| Компонент | Варианты и правила |
|---|---|
| ActionButton | `default` — основное действие; `outline` — второстепенное; `ghost` — контекстное; `destructive` — подтверждаемое удаление. Другие варианты базового Button доступны, но новые цвета для действий не добавлять. |
| Button | Зона нажатия 48 dp; текст переносится. Использовать ActionButton для обычных текстовых действий. |
| Card | Самостоятельная группа: запись, обработка, резюме, реплика. Стандартные секции Header/Content, один владелец padding. |
| Badge | Короткий статус; сам по себе не интерактивен. Имя участника реализовано Button с цветной подложкой. |
| Input | Видимая граница, доступное имя, placeholder без снижения контраста; имя вводится в диалоге. |
| ModalShell | Заголовок, явное «Закрыть», Android Back через onRequestClose, ограничение высоты и прокрутка содержимого. Клавиатура учитывается через KeyboardAvoidingView. |
| TranscriptItem | Имя → время → текст; время относится к исходной записи. На экране читаемые часы, в JSON остаются целые миллисекунды. |
| ExportBar | Основное действие — JSON, рядом вторичные TXT и просмотр JSON. Footer находится внутри safe area. |

Пример использования:

```tsx
import { ActionButton } from './src/components/ui/action-button';

<ActionButton label="Расшифровать" onPress={start} disabled={busy} />
<ActionButton variant="outline" label="Отменить обработку" onPress={cancel} />
<ActionButton loading label="Создание резюме" />
```

Не задавать вручную высоту 32/40 dp поверх базовой кнопки. Не помещать удаление внутрь другой нажимаемой области: в истории открытие и удаление — соседние действия.

## Состояния и текст

- Без записи: «Выбрать запись»; пояснить поддерживаемые форматы и локальную обработку.
- Запись выбрана: показать полное имя и размер; «Расшифровать» — главное действие, замена файла — вторичное.
- Подготовка / определение участников / резюме / сохранение: индикатор ожидания и название стадии. Не придумывать процент или оставшееся время.
- Распознавание: считать завершённые реплики, если движок прислал корректные `completed/total`. Полоса относится к этой стадии, не ко всей длительности обработки. Сообщение «Распознано реплик: N из M» объясняет её смысл.
- Отмена: существующий обработчик отправляет кооперативную отмену. Нельзя сообщать об освобождении моделей до ответа движка.
- Пустой результат: «Речь не обнаружена»; ноль реплик не заменяется демонстрационным диалогом.
- Ошибка: причина и возможность повторить действие. Ошибка резюме не должна скрывать готовую расшифровку.
- Резюме: отдельная карточка, предупреждение проверять важные факты. Обновление резюме не меняет исходные реплики.
- Технические названия ASR/моделей и ссылки на страницы задания живут в документации. JSON остаётся видимой пользовательской функцией экспорта.

Строгий экспорт и сервисы обработки остаются отдельным слоем; компоненты не добавляют поля в JSON. Имена используются в UI/TXT, исходный speaker_id сохраняется в JSON.

## Проверки и воспроизведение

Из `app/`:

```powershell
npm ci
npm run theme:generate
npm run theme:check
npm run typecheck
npm run lint
npm run test:design
npm run test:integration
npm run ui:export
```

`ui:export` собирает изолированную веб-галерею реальных компонентов в `artifacts/ui-preview/`. На время экспорта скрипт меняет entry point и восстанавливает его в finally; не запускать параллельно с production export. Галерея содержит явно тестовые данные, не импортируется production `index.ts`, не запускает ML и не является дополнительным сценарием приложения. После аварийного завершения процесса проверить, что `main` в package.json равен `index.ts`.

Статическую галерею можно открыть локально: `python -m http.server 8765 --bind 127.0.0.1 --directory artifacts/ui-preview` из корня репозитория. Снимки и результаты проверки — в [отчёте UI](ui-review-2026-11-07.md).

Проверки контраста тестируют пары обычного текста на 4.5:1, в том числе имена участников. Disabled — отдельное состояние; тест контраста не равен аудиту всех состояний и всей доступности. Проверка прогресса запрещает фиктивные значения для неизвестных стадий/невалидных чисел.

Перед финальной сдачей на Redmi проверить: Android-клавиатуру в переименовании; жестовую/трёхкнопочную навигацию и safe area; TalkBack, порядок фокуса и Android Back; размер шрифта 1.3× и 2×; длинный JSON и большую историю; реальную обработку и экспорт в авиарежиме. Web screenshots и Android JS bundle эти проверки не заменяют.
